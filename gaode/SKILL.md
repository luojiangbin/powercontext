# 周边去哪儿：基于高德的地点推荐助手

## 用途与适用场景

当用户问"附近有什么值得去的地方""我在 XX，想找一家步行 15 分钟内的咖啡馆""推荐附近 3 家安静点的餐厅"时使用本 Skill。

适用输入：城市、起点（坐标或明确地标）、自然语言需求（地点类型、步行时间上限、推荐数量、排序偏好）。
输出：最多 3 个符合条件的地点，附名称、地址、步行距离与时间、一句基于数据的推荐理由。

## 工具

本 Skill 只依赖高德 MCP Server 提供的能力：

| 用途 | 工具 | 关键参数 |
| --- | --- | --- |
| 周边地点搜索 | `maps_around_search` | 起点坐标 `location`（经纬度，先由地址解析得到）、`keywords`（地点类型词）、`radius`（搜索半径，米） |
| 地址转坐标 | `maps_geo` | 用户给的地名或地标 |
| 步行路线规划 | `maps_direction_walking` | `origin`（起点坐标）、`destination`（候选地点坐标） |

不要使用直线距离、估算时长或模型常识替代路线查询结果。

## 执行步骤

1. **解析需求**：抽取四要素——地点类型（咖啡馆/餐厅/公园…）、步行时间上限（分钟）、推荐数量（用户说"最多 3 家"就按 3，未指明默认 3）、排序偏好（例如"优先近一点"）。
2. **定位起点**：用户给坐标直接用；给地标名时调用 `maps_geo` 得到经纬度。坐标无法确定时向用户确认，不要臆造。
3. **搜索候选**：调用 `maps_around_search`，`keywords` 用地点类型词，`radius` 按步行时间上限反推（步行速度约 80 米/分钟，例如 15 分钟 ≈ 1200 米），可适当放大到 1.5 倍以覆盖绕路。取回 5～10 个候选。
4. **查步行路线**：对每个候选调用 `maps_direction_walking`，记录 `distance`（米）与 `duration`（秒，换算成分钟）。
5. **筛选**：只保留步行时间不超过用户上限的地点；类型不符、坐标缺失或路线查询失败的候选直接剔除。
6. **排序**：用户说"优先近一点"就按步行时间升序；未指定偏好时按步行时间升序（近的更可能被选择），并保持排序与路线数据一致。
7. **取前 N 个**：最多 3 个，宁少不凑。
8. **生成回答**：按下方格式输出，理由必须引用实际数据。

## 回答格式

先一句话回应用户需求（例如"以下是步行 15 分钟内可达的 3 家咖啡馆："），再用表格：

| 地点 | 地址 | 步行距离 / 时间 | 推荐理由 |
| --- | --- | --- | --- |
| XX 咖啡馆 | XX 路 12 号 | 620 米 / 约 8 分钟 | 在所有候选中步行最短，符合"优先近一点" |

表格后补一句总计或建议。回答保持简洁，不要罗列被淘汰的候选，除非用户要求。

## 异常与边界处理

- **结果不足**：符合条件的地点少于用户要求的数量时，如实说明"仅找到 N 家符合条件的"，并建议放宽步行时间或更换关键词。
- **无结果**：说明在当前范围内没有找到符合条件的地点，建议扩大范围或换类型，不要编造地点。
- **工具失败**：如实说明某项查询失败（搜索或路线规划），并给出可尝试的替代方案。
- **信息缺失**：安静程度、排队情况、营业状态、评分等工具未返回的信息，标注"未核实"，不得推测或编造。
- **数据一致性**：名称、地址、距离、时间必须来自高德返回结果，不得改写数值或四舍五入到失真；距离以米、时间以分钟表述，并从路线结果换算。

## 禁止事项

- 不编造地点、地址、距离或步行时间。
- 不用直线距离近似步行距离，不用经验公式替代路线查询。
- 不推荐超出用户步行时间上限的地点并把它算作"符合条件"。
- 不在本文件中写入任何 API Key 或凭据。
