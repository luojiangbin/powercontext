# 技术说明

## 一、选题与技术结合

本题要求"使用 seekdb 或 PowerContext 完成开发"。本作品**两者都用了**，且 seekdb 承担的是
最核心的角色——**Dify 的部署数据库**：

- **seekdb**：Dify 的全部业务数据（172 张表）与插件管理数据（13 张表）存储在 seekdb 中，
  通过 Dify 官方原生支持（`DB_TYPE=seekdb` + `VECTOR_STORE=seekdb`）接入，零兼容层。
- **PowerContext**：应用层记忆——每个对话会话创建一个 scope（按对话 id 幂等），每轮剧情
  以 `story-state` 原子记忆写入，下一轮通过 `context/prepare` 组装历史剧情注入 LLM 提示词。
- **MiniMax**：对话生成模型（minimax-text-01），通过 Dify 官方 minimax 插件接入。
- **Dify**：流程编排与交付——Chatflow 画布把"读记忆 → 续写 → 写记忆"串成 8 节点工作流，
  发布为标准 HTTP API。

## 二、seekdb 适配工作（本作品对 seekdb 兼容性的贡献）

Dify 官方数据库迁移脚本 `2026_08_27_1200-5578e028b2f2_migrate_legacy_model_types.py`
使用了 MySQL `TEMPORARY TABLE` 语法，seekdb 报
`MySQL compatible temporary table not supported`，导致迁移中断、Dify 无法初始化。

**适配方案**：将该迁移中的临时表改为普通表（迁移只执行一次，普通表语义等价；先
`DROP TABLE IF EXISTS` 保证重试安全），并构建补丁镜像 `dify-api-seekdb:1.18.0`。
补丁文件与构建方式见 `deploy/seekdb-patch/`。

适配后 `flask upgrade-db` 在 seekdb 上**全量迁移成功**，Dify 正常启动、建应用、跑工作流。

## 三、模型供应商插件化适配（无外网环境）

Dify 1.18 将模型供应商全面插件化，官方 marketplace（marketplace.dify.ai）在部分网络环境
不可达。本作品从 `langgenius/dify-official-plugins` 仓库取 minimax 官方插件源码，按官方
打包格式手工制作 `.difypkg`（zip、manifest.yaml 位于根目录），经控制台 API
`plugin/upload/pkg` + `plugin/install/pkg` 完成安装，插件在 daemon 中正常启动并对外提供
27 个模型（llm / text-embedding / tts）。

## 四、工作流设计

| 节点 | 类型 | 作用 |
|---|---|---|
| 开始 | start | 接收玩家一句话输入（sys.query） |
| 创建会话 | http-request | POST /v1/scopes，`idempotency_key=dify-<conversation_id>`，同一对话复用同一 scope |
| 解析会话ID | code | 从响应 JSON 提取 scope_id |
| 读取剧情 | http-request | POST /v1/context/prepare（scope_id + 本轮输入 + max_bytes=2000） |
| 解析剧情 | code | 提取 content（PowerContext 组装好的历史剧情文本） |
| 离谱续写 | llm | minimax-text-01；系统提示词设定"只推进一步、结尾给 2-3 个选项"的离谱冒险主持人人设；用户提示词注入历史剧情 + 本轮输入 |
| 写回剧情 | http-request | POST /v1/memory/remember（kind=story-state，text=LLM 输出） |
| 结束 | end | 输出续写文本 |

**记忆一致性**：scope 按对话幂等创建；每轮写回为新增原子记忆（不可变、可审计），读取通过
prepare 组装全部历史；同一对话多轮、跨请求均正确。

## 五、复现说明

1. Docker 环境 + `docker compose --profile seekdb up -d`（`.env` 关键配置见 `deploy/.env.example`）
2. 构建 seekdb 适配镜像：`cd deploy/seekdb-patch && docker build -t dify-api-seekdb:1.18.0 .`
3. 首次启动后执行 `docker exec <api容器> flask upgrade-db`（一次性迁移）
4. 初始化管理员（http://localhost/install）
5. 安装 minimax 插件（`deploy/minimax.difypkg`，控制台"插件→上传"或 API `plugin/upload/pkg`）
6. 在"模型供应商"里为 minimax 填入 API Key
7. 导入 `越聊越离谱的冒险故事.yml` → 发布 → 用 API Key 调 `/v1/chat-messages`
8. PowerContext 服务需监听 0.0.0.0:8000；若 `host.docker.internal` 无法解析，
   在 compose 里将 extra_hosts 改为宿主机网桥网关 IP（本环境为 172.18.0.1）
