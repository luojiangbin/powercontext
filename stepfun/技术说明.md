# 一页技术说明

## 1. 模型与量化

- 模型：`Xenova/all-MiniLM-L6-v2`（Apache-2.0，384 维，Hugging Face 开源）
- 量化方案：ONNX INT8 动态量化（`model_quantized.onnx`），基线为 fp32（`model.onnx`）
- 体积与压缩比：

| 精度 | 模型文件体积 | 压缩比 |
|---|---|---|
| fp32 | 86.2 MB | — |
| INT8 (q8) | 21.91 MB | **3.93×** |

- 质量对比（固定评测集 12 文档 / 6 查询，余弦相似度排序，同一浏览器）：

| 精度/后端 | Recall@5 | nDCG@5 |
|---|---|---|
| fp32 / WebGPU | 0.667 | 0.602 |
| INT8 / WASM | 0.583 | 0.602 |

结论：INT8 量化后 Recall@5 下降 12.5%、nDCG@5 持平，质量无明显下降。

## 2. 端侧运行与降级

- 运行时：Transformers.js 3.3.3（onnxruntime-web），embedding 全程在浏览器本地计算，无云端推理 API
- 后端选择：优先 WebGPU；加载失败或 **INT8 自检未通过**时自动降级 WASM，界面徽章明确提示后端与原因
- 自检：加载后对 6 句（3 主题×2）做聚合相似度检验（同主题均值 > 跨主题均值 + 0.05），拦截量化推理异常
- 实测发现：本机（Intel 核显 + Edge 155）WebGPU EP 下 INT8 推理结果异常（Recall@5 0.333），自检拦截并降级 WASM 后恢复 0.583；fp32 在 WebGPU 上正常。该路径已在界面明示，属环境兼容性保护，非功能缺陷

## 3. seekdb 使用

- 接入：seekdb-js 1.4.0（server 模式），堆表（无主键，混合搜索要求）
- 表结构：

```sql
CREATE TABLE docs (
  doc_id VARCHAR(64), session VARCHAR(64),
  title VARCHAR(200), content TEXT, vec VECTOR(384),
  FULLTEXT INDEX idx_content(content) WITH PARSER ik,
  FULLTEXT INDEX idx_title(title) WITH PARSER ik,
  VECTOR INDEX idx_vec(vec) WITH (distance=cosine, type=hnsw, lib=vsag)
);
```

- 混合检索：`DBMS_HYBRID_SEARCH.SEARCH` 一次调用完成 query_string（content^2 / title^1.5，IK 中文分词）+ KNN（cosine）+ RRF 融合（rank_window_size=100, rank_constant=60），检索由 seekdb 完成，客户端不做两路拼合
- 会话：`session` 列 + term 过滤（query 与 knn 双路过滤），保证切换会话后结果一致
- 增量写入与刷新：导入后立即对最新文档做可见性轮询（hybrid 查询命中 doc_id），确认索引刷新完成才返回成功；写入前不做客户端缓存，连续导入均可检索

## 4. 状态与性能优化

- 优化点：① embedding 批处理（批大小 8，减少 GPU/WASM 调用与调度开销）；② 模型权重本地托管（去外网依赖，冷加载更快更稳）；③ INT8 量化（体积 3.93× 压缩）；④ 索引刷新可见性确认（写入-可检索闭环）；⑤ 首次/预热计时分离（模型加载单独计时，不计入查询延迟）
- 实测（Edge 155 / Intel 核显，5 篇文档，本机 seekdb）：

| 阶段 | INT8 + WASM（降级） | fp32 + WebGPU |
|---|---|---|
| 模型加载（热） | 505 ms | 667 ms |
| 文档向量化（5 篇，批 8） | 82 ms | 178 ms |
| 查询向量化 | 7 ms | 12 ms |
| 写入+索引刷新 | 118 ms | 22 ms |
| seekdb 混合检索 | 8 ms | 4 ms |
| 端到端查询 | 20 ms | 20 ms |

（冷加载首次需下载权重：本地托管下 INT8 ≈ 0.5s 内；数字为单次运行实测，评测页可复跑取中位数）
